CHAPTER 03

Stage 2: Polynomial Rolling Fingerprinting ($O(1)$)

How do you compare hundreds of thousands of word combinations without stalling the processor?

PlagiGuard converts normalized token streams into sliding N-gram windows. Instead of re-hashing $K$ words on every step in $O(K)$ time, our Polynomial Rolling Hash updates in constant $O(1)$ time.

H = \left(\sum_{i=0}^{k-1} x_i \cdot B^{k-1-i}\right) \pmod p

By utilizing Double Prime Moduli ($10^9+7$ and $998244353$), we virtually eliminate accidental hash collisions across millions of unique academic phrases.

How was this score calculated? (Mathematical Transparency)

1. Jaccard Similarity Coefficient:

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|} \times 100\%$$

Measures the shared unique N-grams relative to the combined unique N-gram vocabulary across both documents. A score of 100% indicates identical shingle sets.

2. Directional Document Coverage:

$$O(A \to B) = \frac{|A \cap B|}{|A|} \times 100\%$$

Measures the proportion of Document A's unique N-grams that appear within Document B. Directional overlap captures cases where a short assignment is copied into a longer paper.

Inside the C++ Detection Engine

Core Data Structure

1. Custom Hash Table

Implements generic separate chaining with dynamic singly-linked list nodes. Automatically doubles bucket array capacity when load factor $\alpha \ge 0.75$.

Time: $O(1)$ avg, $O(N)$ worst Space: $O(N)$
bucket = hash(key) % capacity;
node = buckets[bucket];
while(node) { if(node->key == key) return node->val; }
String Hashing

2. Rolling Double Hash

Maintains sliding window hash in $O(1)$ arithmetic using two large prime moduli $P_1 = 10^9+7$ and $P_2 = 998244353$ with base $B = 31$.

Slide: $O(1)$ Collision: < $10^{-18}$
H = ((H - old * B^{k-1}) * B + new) % P;
Pattern Matching

3. Rabin-Karp Matcher

Locates candidate matching passages using the rolling hash table, followed by mandatory deep token sequence verification to eliminate collisions.

Time: $O(N + M)$ expected Space: $O(N)$
if (hashA == hashB && verifyTokens(toksA, toksB)) {
recordMatch(source, target);
}
Text Processing

4. Word N-Gram Generator

Partitions normalized word tokens into overlapping contiguous sequences of size $N$, mapping byte offsets and paragraph indices.

Window: 3 to 10 words Time: $O(W \cdot N)$
Set Theory

5. Jaccard & Directional Overlap

Computes symmetrical Jaccard similarity and asymmetrical directional document coverage using custom hash table set operations.

$J = \frac{|A \cap B|}{|A \cup B|}$ $O = \frac{|A \cap B|}{|A|}$
Priority Queue

6. Binary Max-Heap

Maintains dynamic array of document pairs ranked by similarity score. Supports $O(N)$ build-heap and $O(K \log N)$ top-K match extraction.

Insert: $O(\log N)$ Extract Max: $O(\log N)$
Graph Theory

7. Document Similarity Graph

Weighted adjacency list modeling document relationships where edge weights represent Jaccard scores exceeding the threshold.

Layout: 2D Force-Directed Threshold: Configurable
Graph Traversal

8. Breadth-First Search (BFS)

Explores document similarity clusters level-by-level using a FIFO queue to discover nearest related academic manuscripts.

Time: $O(V + E)$ Order: Level-by-level
Graph Traversal

9. Depth-First Search (DFS)

Traverses deeply into document citation and copying chains using an explicit LIFO stack and tracks connected components.

Time: $O(V + E)$ Order: Deepest branch
Dynamic Programming

10. Longest Common Subsequence

Computes 2D dynamic programming matrix to align token sequences and reconstruct revision additions, deletions, and unchanged text.

Time: $O(N \cdot M)$ Space: $O(N \cdot M)$
Tree Structure

11. Vocabulary Prefix Trie

Manual pointer-based trie storing indexed vocabulary for instant prefix queries, keyword lookups, and dictionary pruning.

Lookup: $O(L)$ where $L = |word|$ Space: $O(\Sigma \cdot N)$
